## Submit a hardware report

The fastest way to help the next person with your laptop is a hardware report. Run one command on your Omarchy machine, paste the output into the [submit page](/hardware/submit/), review exactly what will be shared (only the machine, kernel, and device lines; hostname and logs are stripped in your browser), mark what works, and submit. Reports become the per-model pages.

## Fix a fix

Every fix page has an "Improve this page" link that opens the Markdown source on GitHub. If a fix stopped working on a newer version, say which version and what happened. If you found the original fix in a thread we did not credit, add yourself under `credits` and we will merge it.

## Write a new fix page

Pick an error people actually hit. Search the [Omarchy issues](https://github.com/omacom/omarchy/issues) and [discussions](https://github.com/omacom/omarchy/discussions) for it. Write the page in your own words: the exact error string as the title, a two-sentence answer, the fix as numbered steps, a way to verify, and links to every source thread. Copy an existing page's frontmatter. Do not paste other people's comments verbatim.

## Reference data

Commands, keybindings, the menu tree, and migrations are generated by scripts in `scripts/` from the omacom/omarchy source. If a script misparses something, fix the script, not the output.

## Ground rules

No installers, no mirrors, no affiliate links, no official logo, no claiming to be Omarchy. Disagree with the project as much as you like, with sources.
